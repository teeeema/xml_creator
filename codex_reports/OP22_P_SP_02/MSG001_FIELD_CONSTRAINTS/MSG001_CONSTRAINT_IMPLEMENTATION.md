# Реализация блока «Ограничения»

## Scope

Изменение действует только для существующего прототипа карточки:

`P.SP.02` → `P.SP.02.TRN.001` → `P.SP.02.MSG.001` → `R.IP.SP.02.002`.

## Data flow

`StructureFieldDefinition.constraints` → `GuiViewModel._field_info_constraints()` → `selectedFieldDetails.constraints` → `HomePage.qml`.

Никакой runtime-зависимости от PDF/RTF нет. Нормативные YAML, Knowledge Base, rules engine и другие процессы не изменялись.

## Presentation rules

- `Шаблон` выводится без изменения исходного regex.
- Человеческое пояснение добавляется только для явно разрешённых простых шаблонов: `\d{5}`, `\d{4}`, `\d+`, `[A-Z]{2}`.
- Для сложного regex выводится только исходный шаблон.
- `Мин. длина` и `Макс. длина` преобразуются в отдельные читаемые строки с количеством символов.
- Для подтверждённой даты ISO 8601 выводятся `Формат` и краткое пояснение.
- Текст о классификаторе не превращается в enum и не создаёт допустимые значения.
- `Множитель` остаётся отдельным свойством карточки и не считается ограничением.
- Если явных поддерживаемых ограничений нет, секция `Ограничения` полностью скрыта.

Существующие `ScrollView`, `Text.Wrap`, `Text.PlainText`, выбор GROUP-полей, Unicode sanitation и отдельный блок `Правило заполнения в MSG.001` сохранены.
