# P.SP.02.MSG.001 — панель «Сведения о поле»: до и после

## Область изменения

Трассировка: **ОП №22 → P.SP.02 → P.SP.02.TRN.001 → P.SP.02.MSG.001 → R.IP.SP.02.002**.

Прототип включается только при одновременном совпадении:

- процесс `P.SP.02`;
- транзакция `P.SP.02.TRN.001`;
- сообщение `P.SP.02.MSG.001`;
- структура сообщения `R.IP.SP.02.002`.

Для `P.SP.02.MSG.002+` и сообщений других процессов сохраняется прежняя ветка `selectedFieldInfo` / `controller.field_help(...)`.

## До

Правая панель всегда показывала общий технический текст `controller.field_help(...)`. В одном представлении смешивались нормативные сведения о реквизите и внутренние сведения приложения: XML/path, kind/type, policy/status/origin/source и другие служебные маркеры.

Групповой контейнер `GROUP` использовался как заголовок секции и не мог быть выбран для просмотра собственных нормативных метаданных.

## После — только для P.SP.02.MSG.001

При выборе реквизита панель «Сведения о поле» показывает только четыре блока:

1. **Имя реквизита** — нормативное `official_name` без конечного технического QName-суффикса. Семантические скобки в названии сохраняются.
2. **Описание реквизита** — `description` из `R.IP.SP.02.002`.
3. **Тип данных** — QName типа и первый идентификатор модели из `datatype_text`, например `ipsdo:IPDocKindCodeType` + `(M.IP.SDT.00009)`. Ограничения и шаблоны из `datatype_text` не выводятся.
4. **Множитель** — только структурная кратность из `min_occurs` / `max_occurs`: `1`, `0..1`, `1..*` и т. п.

Когда поле не выбрано, выводится ровно:

> Выберите поле, чтобы посмотреть его нормативное описание.

Заголовок группы `SectionHeader` теперь также передаёт путь выбранного контейнера во ViewModel. При этом прежнее действие клика — сворачивание/разворачивание секции — сохранено.

## Исключённые из прототипа сведения

Для `P.SP.02.MSG.001` в новой панели не выводятся XML, XML path, внутренний kind/type, `Normative input policy`, `UNRESOLVED_INPUT_POLICY`, `Normative value source`, UI policy/origin, `Source`, `source_id`, `VERSION_PLACEHOLDER_TEST`, внутренние статусы и другие отладочные поля.

## Изоляция

Изменение локализовано в `GuiViewModel` и условном QML-рендеринге. Общая модель полей, XML-движок, rules engine, нормативные YAML/KB и метаданные других сообщений не изменялись. RTF во время работы GUI не читается.
